# Plan: 区切り1つの数は数式として組む (#2991)

Issue: https://github.com/receptron/mulmoclaude/issues/2991

## 1. 症状

`円周率は $3.141$ です` が数式にならず、`$3.141$` のまま本文に残る。
`$3.14159$` は組まれるので、著者から見れば桁数で挙動が変わる。

## 2. 原因

ルール5の `isMoneyShaped()` が「区切りが1つで、その後ろがちょうど3桁なら
金額」と読む。`3.141` はこの形に一致するため `$1.500$` と同じく価格として
扱われる。この読み方は #2985 で意図的に選ばれたもので、`$1.500$` /
`$0.100$`（燃料の単価）を金額にするために必要だった。

## 3. 調べたこと — この分岐は何を買っていたのか

実測した。**現実の通貨の散文は、ルール5に到達する前にルール1〜4で全て
落ちている**:

| 書き方 | 落とすルール |
|---|---|
| `価格は $1,000 です` | 閉じ `$` が無い |
| `$1,000 と $2,000` | ルール3（閉じ前が空白） |
| `合計 $1,000から$500` | ルール3 |
| `$1,000-$2,000` | ルール4（閉じ後が数字） |
| `US$1,000` | ルール1（開き前が英数字） |
| 表の各セル | セルごとにトークナイズされる |

残るのは `$1,000$` ── 両端に `$` を書いた形だけ。これは f2af349 が `$5$`
について既に「価格を書く人は `$1,000` と書く。**二重のデリミタ**こそが
数式の印である」と読んだのと同じ形。ルール5は `$5$` と `$1,500$` に
正反対の読み方を当てていた。

一方この分岐が落としていたもの: π `3.141` / √2 `1.414` / e `2.718` /
φ `1.618` / γ `0.577` / アボガドロ `6.022` / g `9.807` / `0.001` / `1.000`。

## 4. 変更

`isMoneyShaped` を **区切り2つ以上** だけに絞る。

```ts
if (!runs.every((run) => DIGITS.test(run))) return false;
return runs.length > 2;
```

区切り2つ以上（`1.000,50`、`12,345,678`）は「桁区切りと小数点の両方を
持つ」形で、誰も計算に使わない書式なので金額のまま残す。

## 5. テスト

`test_numberShape.ts` を新設し、この境界だけを網羅する（41件）:

- 区切りの個数 0 / 1 / 2 / 3 / 多数
- 区切り1つの後ろの桁数 1〜6 ── 旧ルールが3だけを切っていた不連続の不在
- 先頭ランの長さ、先頭ゼロ
- 区切りの種類（`.` `,` 半角空白 タブ U+3000 混在）と、区切りでないもの（`:` `/` `-`）
- #2991 が壊していた数学定数12件を名前付きで
- 数として壊れた形（空ランが出る `1,,000` / `1000.` / `.5`）
- **通貨の散文がルール5に到達しないことの証拠**（11件）── この変更の根拠そのもの
- `$$…$$` はこのルールの対象外
- 単体関数の答えと、文書としてレンダリングした答えの一致

既存の `test_mathExtension.ts` / `test_mathInDocuments.ts` の期待値も
新しい読み方に合わせて更新する。

## 6. 検証

ミューテーションで検出力を測る。特に **旧ルールに戻す変異**が赤くなること。
